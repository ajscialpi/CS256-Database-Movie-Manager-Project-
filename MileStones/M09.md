## M09 — Related-Data Report

### 1. What I Worked On

For MovieVault, I added a report that answers, "How many reviews does each movie
have, and what is its average review rating?" The report includes movies that
do not have reviews yet. It uses the existing database and page styling.

### 2. Report SQL

The query is in [sql/m09_movie_review_report.sql](../sql/m09_movie_review_report.sql).
It joins `cs256_m05_movievault.movies` and `cs256_m05_movievault.reviews`.
The live table definitions were checked on King's before the query was written.
The review `rating` column is `numeric(3,1)`, cannot be null, and allows 0 through 10.
The movie's `content_rating`, such as PG, is a different field and is not averaged.

The query uses `LEFT JOIN` to keep every movie, `COUNT(r.review_id)` to count
reviews, and `ROUND(AVG(r.rating), 2)` to show the average to two decimal places.
It groups by the movie ID, title, genre, and release year. Movies with the most
reviews appear first, followed by title and movie ID to make the order predictable.
Unlike the home search, this report includes all movies without a 25-row limit.

### 3. Report Page

The Flask route is `/reports/movie-reviews` in
[app.py](../backendconnection/app.py). It calls `get_movie_review_report()` in
[repository_postgres.py](../backendconnection/repository_postgres.py), which
loads the SQL file and uses the existing `DATABASE_DSN` connection method.

[movie_review_report.html](../templates/movie_review_report.html) displays Movie,
Genre, Release Year, Total Reviews, and Average Rating (out of 10). The home page
has a Movie review report link, and each movie title links to its saved record.
The table can scroll sideways on a small screen using the existing stylesheet.

A movie without reviews shows 0 reviews and N/A for its average. An actual
zero rating displays 0.00. If there are no movies, the page says so. A database
or missing-configuration error displays a general message with HTTP 503 without
showing connection details.

### 4. Row Detail and Join Keys

- One row in `movies` represents one movie. Its primary key is `movie_id`.
- One row in `reviews` represents one saved review. Its primary key is
  `review_id`. Its foreign key `movie_id` references `movies.movie_id`.
- One result row represents one movie and its review totals. The join is
  `r.movie_id = m.movie_id`.

Each review matches one movie. Only these two tables are joined, so another
one-to-many table cannot multiply the review rows. Grouping by movie ID keeps
different movies separate even when their titles are the same. Counting
`review_id` instead of `COUNT(*)` avoids counting the empty placeholder row
created by the left join when a movie has no reviews. Reviews with the same
rating still count separately.

### 6. Report Limitation

The average only reflects reviews currently saved in MovieVault. A movie with
very few reviews may have an average that does not represent everyone's opinion.
For example, Lantern Harbor's 8.00 average came from only one review.
A movie without reviews has no available average, not a zero-star average.
